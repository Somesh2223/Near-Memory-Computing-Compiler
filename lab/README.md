# Lab exercises shown on NEMO-C

Each program here shows one Compiler Design lab exercise being done by the real
compiler. They are also listed under **Lab exercises** in the web frontend (`make web`).

| Lab exercise | Program | Command | What it shows |
|---|---|---|---|
| Ex 2 Lexical analysis (keywords, identifiers, literals, operators, comments) | `ex2_lexer.nmc` | `--dump tokens` | Every token with line:col; `<=` and `+=` are one token (longest match); comments are removed |
| Ex 2 SET 2 Invalid identifiers | `ex2_bad_identifiers.nmc` | `--dump tokens`, `--check` | `value@` is a lexical error; `2marks` is the number 2 then `marks`, a syntax error |
| Ex 4 Symbol table (redeclaration, undeclared use, scopes) | `ex4_symtab.nmc` | `--check` | 3 errors in one run: redeclared `a`, undeclared `c`, loop index `i` used outside its scope |
| YACC 1 printf syntax | `yacc_print_bad.nmc` | `--dump ast` | 2 valid and 4 invalid `print` statements, each error with line:col |
| YACC 3 if-else syntax | `yacc_ifelse_ok.nmc`, `yacc_ifelse_bad.nmc` | `--check`, `--dump ast` | Nested if-else accepted; 4 broken forms rejected, parser recovers after each |
| YACC 4 for-loop syntax | `yacc_for_ok.nmc`, `yacc_for_bad.nmc`, `yacc_for_semantic.nmc` | `--check`, `--dump ast` | Valid loops; 3 syntax errors; 3 loops that parse but break semantic rules |
| Ex 5 Three-address code (if-else, `a = b * -c + b * -c`) | `ex5_3ac.nmc` | `--dump ir`, `--emit-dot cfg`, `--dump cse` | 3AC with temporaries; the if-else as CFG blocks; `b * -c` computed once |
| Ex 6 Code optimisation (constant propagation, CSE, dead code) | `ex6_optimise.nmc` | `--dump constfold`, `--dump cse`, `--dump dce` | c = 30, d = 10, e = 300; `s = p + q` reuses `t`; `z = 10` removed |

Not covered by NEMO-C, and why:

- **Ex 1 (file operations, month-code puzzles)** and the **Lex validators (PAN, e-mail,
  password)** are warm-up programs, not compiler phases.
- **Ex 3 Recursive-descent parser** and **FIRST/FOLLOW**: NEMO-C's parser is LALR(1),
  bottom-up, generated by bison. It does not use FIRST/FOLLOW the way an LL(1) or
  recursive-descent parser does; bison computes LALR lookahead sets instead (the states
  and lookaheads are in `build/parser.output`).
- **YACC 2 scanf** and **YACC 5 while**: the NEMO-C language has no input statement and
  no while loop. Only `for` loops with constant bounds exist, because the cost model
  needs exact trip counts.
